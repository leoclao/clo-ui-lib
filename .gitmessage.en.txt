# Use Conventional Commits: https://www.conventionalcommits.org
#
# Format:
# <type>(<scope>): <short description>
#
# <type>     : Type of change (see below)
# <scope>    : Affected package/component (e.g., button, modal, docs, cli)
# <desc>     : Short summary (lowercase, no trailing period)
#
# Example:
# feat(button): add loading state to button
# fix(modal): fix mobile close button behavior
# docs(readme): update installation instructions
#
# Types:
# - feat      : A new feature
# - fix       : A bug fix
# - docs      : Documentation only changes
# - style     : Code style changes (formatting, etc)
# - refactor  : Code refactoring (no new features or bugs fixed)
# - test      : Adding or updating tests
# - chore     : Build, CI, tooling updates
# - perf      : Performance improvements
#
# After the first line, add a longer description if needed:
#
# - Why the change was necessary
# - What alternatives were considered
# - Related issues: Closes #123
